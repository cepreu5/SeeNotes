За да постигнем това, трябва да разделим двата случая на стартиране: „безшумно“ (при Refresh) и „изрично“ (през екрана за вход).

Предлагам следния подход:

Промяна в 
startApp
: Добавяме параметър на функцията, например isExplicitLogin.
Подаване на флага:
Когато 
startApp
 се вика автоматично (silent start), флагът ще е false.
Когато се вика от успешното удостоверяване (callback-а на Google бутона), флагът ще е true.
Условна проверка: В 
startApp
 ще викаме 
checkWhitelist()
 само ако isExplicitLogin е истина.
Ето как би изглеждал кодът:

В началото на 
startApp
:
javascript
async function startApp(isExplicitLogin = false) { // Добавяме параметъра с default стойност false
    if (isAppStarted) return;
    // ... останалия код ...
При викането на 
checkWhitelist
 (около ред 1917):
javascript
authToken = authResult.tokenData;
        
        // Викаме лога САМО ако потребителят е минал през логин екрана
        if (isExplicitLogin) {
            checkWhitelist();
        }
В 
initLoginPage
:
Случай 1 (Екран за вход - Когато потребителят кликне бутона): Във функцията, която обработва отговора от Google (callback-а), променяме извикването на:

javascript
startApp(true); // Указваме, че е изричен логин
Случай 2 (Silent start - Около ред 843): Тук оставяме извикването без параметър (или изрично false):

javascript
if (hasToken && !isLogout) {
    startApp(); // Ще използва default стойността false и НЯМА да прави запис
}
Допълнително в самата 
checkWhitelist()
: Трябва да премахнем проверката if (!sessionStorage.getItem('whitelistChecked')), за да може, ако потребителят излезе и влезе отново (Log out -> Log in) в рамките на една сесия, записът да се направи отново.

Така логиката става желязна: Запис се прави само и единствено в момента, в който Google потвърди самоличността на потребителя след интеракция с логин екрана. При всяко друго презареждане (Refresh) функцията просто няма да бъде извикана.
